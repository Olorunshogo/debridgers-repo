# Debridgers Backend Deployment

## Automated Deployment

All services start automatically in `docker-compose.prod.yml`:

- **debridgers-backend** — NestJS API (port 4001/4002)
- **cloudflared** — Cloudflare Tunnel (automatic, no manual command needed)

Database migrations run **locally before deployment**, NOT during deployment.

## Things Worth Knowing Before You Touch This

- DB migrations are explicitly skipped in `deploy.sh` - the comment says to run them against that env's `DATABASE_URL` yourself before deploying. There's no automated migration step.
- Staging and prod share a hostname per the comment in `deploy.sh` (`api-test.debridgers.com` for both dev and prod entries) - that looks like it might be a stale comment since `.gitea/workflows/backend.yml`'s header says prod is `api.debridgers.com`. Worth double-checking your Cloudflare tunnel config if you're unsure which hostname currently routes where.
- Required Codeberg secrets: `SSH_PRIVATE_KEY`, `SSH_USER`, `SSH_HOST`, `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`, `ENV_FILE_DEV`/`ENV_FILE_PROD`, `CLOUDFLARE_TUNNEL_CREDENTIALS` - set per Codeberg "environment" (dev and production).
- To trigger a deploy manually without a qualifying push, use `workflow_dispatch` from the Codeberg Actions UI.

## Development Deployment (api-test.debridgers.com)

### First-time VPS setup:

```bash
./deploy/setup-vps.sh root@2.29.22.10 apps/debridgers-backend/.env
```

### Deploy on push to `develop`:

Automatic via Codeberg Actions (`.gitea/workflows/deploy.yml`)

### Manual deployment:

```bash
ssh root@2.29.22.10
cd /opt/debridgers/deploy
IMAGE_TAG=develop CLOUDFLARE_TUNNEL_CREDENTIALS=... bash deploy.sh
```

## Production Deployment (api-test.debridgers.com)

`api.debridgers.com` is retired as of 2026-09-11 - staging and production both resolve through `api-test.debridgers.com`. See the note in `docs/deployment.md` for what's still open on the Cloudflare Tunnel side.

### Prerequisites:

1. Prod Neon database (separate from dev)
2. Prod VPS (Hetzner, same region)
3. Prod `.env` file with `DATABASE_URL` pointing to prod DB

### First-time prod VPS setup:

```bash
# 1. Create prod .env with prod DATABASE_URL
cp apps/debridgers-backend/.env prod.env
# Edit prod.env with production values

# 2. Run setup script (handles Docker, files, secrets)
./deploy/setup-vps.sh root@<prod-ip> prod.env

# 3. Run migrations on prod database
DATABASE_URL=postgresql://...prod... pnpm db:migrate

# 4. Configure Cloudflare failover
# Manually in Cloudflare dashboard:
# - Primary: prod-ip:4002 (health check: /api/v1/health)
# - Secondary: 2.29.22.10:4001 (fallback only)
```

### Deploy on push to `main`:

Manual for now. Use setup-vps.sh or:

```bash
ssh root@<prod-ip>
cd /opt/debridgers/deploy
IMAGE_TAG=main CLOUDFLARE_TUNNEL_CREDENTIALS=... bash deploy.sh
```

## Database Migrations

**ALWAYS run locally BEFORE deployment:**

```bash
# Development
DATABASE_URL=postgresql://...dev... pnpm db:migrate

# Production
DATABASE_URL=postgresql://...prod... pnpm db:migrate
```

Migrations are NOT run automatically during CI/CD.

## Deployment Scripts

- **setup-vps.sh** — One-time VPS setup (Docker, files, .env, secrets)
- **deploy.sh** — Pull image, start services, health check
- **docker-compose.prod.yml** — Service definitions (backend + cloudflared)

## Environment Variables

Key `.env` variables (auto-generated by setup-vps.sh):

| Variable                        | Purpose                    |
| ------------------------------- | -------------------------- |
| `DATABASE_URL`                  | Neon PostgreSQL connection |
| `CLOUDFLARE_TUNNEL_CREDENTIALS` | Tunnel token               |
| `TUNNEL_ID`                     | Tunnel ID                  |
| `PORT`                          | 4001 (dev) or 4002 (prod)  |
| `NODE_ENV`                      | production                 |
| `DOCKERHUB_TOKEN`               | Pull Docker images         |

## Troubleshooting

**Backend not starting:**

```bash
ssh root@<vps-ip>
docker logs debridgers-backend | tail -50
```

**Tunnel not connecting:**

```bash
docker logs debridgers-cloudflared | tail -50
```

**Manual restart:**

```bash
cd /opt/debridgers/deploy
IMAGE_TAG=develop CLOUDFLARE_TUNNEL_CREDENTIALS=... docker compose up -d
```
